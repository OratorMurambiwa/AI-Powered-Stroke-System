# Experimental prediction API v1

Read the [artifact audit and actual CPU gate](experimental-models/medstroke-audit.md) first. This workflow is synthetic-only and opt-in; it imports neither legacy ML/Streamlit authentication nor hosted AI/treatment code.

## Configuration and isolation

Initialize a **fresh** explicit synthetic clinical store version **4**. No v1/v2/v3 file is migrated, adopted or copied. Existing v4 assessment intake, private scans, human review and booking contracts retain their semantics. Set `CLINICAL_INFERENCE_URL` to the explicitly deployed local/private `/api/v1/predict` endpoint and `INFERENCE_SERVICE_KEY` to an operator-generated 32-byte random hex secret. Neither has a default credential. Blank configuration disables new inference; prior results/reviews can still be read by authorized doctors. Non-v4 configuration cannot enable inference. No dotenv discovery or existing credential modification occurs.

Build the worker with `docker build -f inference_worker/Dockerfile -t stroke-inference:milestone4b .`. Dockerfile-specific context rules exclude weights, databases, scans, credentials and unrelated sources. Mount only the confirmed `ml/MedStroke.pt` at `/artifact/MedStroke.pt:ro`. Run nonroot/read-only, private tmpfs, no capabilities/new privileges, 2 CPUs, 1500 MiB memory, 64 PIDs and an **internal private Docker network** with the clinical caller, or equivalent approved local isolation. Do not expose port 8020 publicly. The worker receives image bytes/hash/model hash and its own admission key, never a booking bearer, identity record, path, database handle or arbitrary URL. The child receives no admission key or clinical credentials.

The test helper creates this network/container and random private env file automatically after the image is built. It removes only its own containers/network/env file and never removes volumes. Standalone worker tests use no network at all. Clinical authority calls remain in the separate API/test process.

## Public clinical paths and permissions

All paths require live booking introspection and current mapping/role generation plus **assigned doctor** status. Patient, technician and admin roles cannot request/read/review predictions. This least-privilege milestone does not give technicians access to classifier output. Existing emergency encounter rules and technician human-observation permissions are unchanged.

- `POST /api/v1/clinical/encounters/{encounterId}/predictions`: exactly `{schemaVersion:1,requestId:UUID,scanId:UUID}`. Scan must already be privately stored under this exact encounter. No model choice, filepath, URL, image bytes or client role is accepted.
- `GET /api/v1/clinical/encounters/{encounterId}/predictions`: at most 16 job records, each with nullable experimental result and independent review.
- `POST /api/v1/clinical/encounters/{encounterId}/predictions/{predictionId}/review`: exact versioned request UUID, `expectedReviewVersion:0`, `decision:ACKNOWLEDGED|DISMISSED`, bounded note and `attested:true`. One immutable doctor review, repeatable by the same exact actor/body/key. Competing/changed reviews return 409.

The [versioned JSON contract](../clinical_api/contracts/experimental-predictions-v1.schema.json) defines command, record, job receipt, list and review under `$defs`. Every result identifies the checkpoint digest/version, preprocessing version, exact scan digest/UUID, encounter/prediction UUIDs, requester mapping/role generation, requested/completed UTC times, full three scores in label order, raw max score/class and worker duration. Permanent flags are `experimental:true`, `clinicianReviewRequired:true`, `patientVisible:false`. A review has `diagnosisApproved:false` even after acknowledgement. These are independent records, not generated observations, diagnoses or approved findings.

## Idempotency, bounds and failures

SQLite serializes a durable reservation and audit, then releases the transaction before the HTTP/model call. Requests bind exact encounter/scan/model digest and requesting subject/mapping. Identical completed requests return their saved result; identical currently leased requests return 202/PENDING without starting another job. New or changed actors/bodies cannot take over the request UUID. A failed/expired attempt may be retried by a currently authorized same actor/mapping with the same command, up to **3 attempts**. At most **16 requests per encounter**. No background retries or stored booking tokens.

Each attempt has a random fencing token and **35-second lease**. Lease expiry permits an authenticated retry, not mutation of scan/human findings or cancellation. The worker admits only one job at a time and returns busy for competing jobs; callers record failure for explicit retry. Actual child execution is capped at **20 seconds wall time**, **12 CPU seconds**, with the whole child process group killed/reaped on timeout. Container resource limits are additional controls. Worker HTTP input is at most 1,400,000 bytes; scan validation is the existing restricted 1 MiB PNG validator. Worker responses are at most 4096 bytes and strictly bound to the pinned model/preprocessing/input digest, labels, finite scores, max class and duration. No automatic library/model download or default/Unknown prediction is accepted.

Clinical API revalidates the live session and assignment **after** execution and before fenced completion. Revocation/logout during the job prevents result persistence/disclosure; session expiry/outages fail closed. The final result and completion audit commit together. Model/transport/validation/commit failure cannot produce a successful prediction; known failures record metadata without scores. If storage cannot record failure, the reservation may remain pending until a valid retry. Unknown HTTP outcome can cause recomputation; fencing admits one committed result, not a claim of exactly-once execution. Review and read audits are transactional; audit failure blocks disclosure. Failed/rejected inputs never change human workflow revisions or approved findings.

The adapter uses a 24-second socket timeout and rejects redirects, proxies and malformed/misbound responses. This is not a general absolute HTTP deadline or production service-auth/TLS guarantee. Stale attempts cannot commit after losing the fence; a permanently revoked mapping, exhausted retries or unavailable audit/store can require operator review. No force-unlock, automatic reassignment or background recovery is provided.

Patients never receive predictions, including reviewed ones. The human assessment API continues to expose only its own immutable approved human snapshot; its `inferencePerformed:false` describes that human workflow payload, not the presence/absence of separate experimental records. No model result is copied into that payload, and no prediction updates appointment status, tPA eligibility, prescriptions or treatment plans.
